# 腕上漫画同步器 (AstroBox V4 插件)

基于 Rust 和 WASI Preview 3 (Component Model) 开发的 AstroBox V4 插件，用于管理腕上漫画的漫画源、Cookie、书架数据以及本地漫画导入。

## 功能特性

- 🌐 **漫画源与 Cookie 同步**：通过 Interconnect 将漫画源配置与鉴权 Cookie 下发至穿戴设备
  - 一次读取完整 `/config`，按 key 多选；逐源保留、更新或清空 Cookie，固定快照和设备发送
- 📚 **离线书架管理**：浏览手环本地已缓存漫画与源列表，支持设备端漫画/源删除
  - 支持原生 fetch 的新版快应用通过 HTTP 回传列表及封面二进制；旧客户端或无原生 fetch 的设备使用互联回传
- 📤 **本地漫画导入**：
  - 支持单篇与多章节模式
  - 新版章节导入按稳定作品身份/设备 ID 与真实章号追加或更新；整本发送替换整书，单章更新保留其他章、已有书名/封面和阅读历史
  - 支持封面自定义
  - 自动根据设备参数（JPEG / PNG / LVGL indexed-8）进行图片预处理与滑动窗口分片传输
- 🚀 **内建本地 HTTP 漫画源（API Level 4）**：
   - 宿主侧监听 `0.0.0.0` 动态端口
   - 支持设备上传时优先自动绑定 `127.0.0.1:<实际端口>`，无需填写局域网 IP
   - 回环连接失败或超时后尝试已保存的备用 IPv4；绑定成功后统一使用该地址生成源配置、封面与正文 URL
  - 支持 `/control/health` 服务健康与能力检查
   - 提供 `/control/probe.jpg`、`/control/probe.png`、`/control/probe.bin` 固定探针图片，供设备端原生 fetch 导入联调

## 漫画源与 Cookie 同步

1. 在「漫画源配置」输入完整 API 基础地址，然后点击「读取 / 刷新配置」读取一次 `/config`。输入和失焦只保留草稿，不发请求、不逐字重建输入框；支持 HTTP(S)、IP、localhost、端口和路径前缀，裸地址默认 HTTPS。同步复用本次目录，需要重新获取时再次点击读取按钮。
2. 查看各源名称、key、API 地址并勾选。首次单源默认选中，多源需要明确选择；无效条目标出字段原因且不可勾选，超过 8 条可分页，可全选有效源或清除选择。设备按 key 更新覆盖同 key 配置。
3. 为每个源分别选择「保留 Cookie / 更新 Cookie / 清空 Cookie」。保留不下发，更新需要非空内容，清空发送空字符串；只下发勾选源的修改。Cookie 输入按密码字段展示，连续输入只更新草稿；点击同步时校验最新内容，空白/非法更新在启动及发送前拦截。
4. 点击「同步所选源到设备」。插件固定原目录、所选载荷及设备；旧读取/输入/同步按钮不更新新表单，握手期间入口或连接改变会停止剩余发送。
5. 状态显示配置/Cookie 命令的发送数量，传输异常区分失败及部分发送。现有协议没有设备保存回报，显示「命令已发送，待设备核实」；可读取设备源列表核对配置，并通过源的实际访问结果核对 Cookie。

配置响应最多 256KiB/128 个源，单个控制消息最多 64KiB，Cookie 更新最多 16KiB 且不接受换行/控制字符；超限或地址/HTTP/JSON/字段错误有明确提示。`type` 可选，单篇 `photoPath` 可不含 `<chapter>`，已有扩展字段原样保留。草稿为本次运行内有界状态，按配置入口、key 和 API 地址隔离，刷新同身份可恢复；重启后的持久化另行完善。

此功能最低快应用版本仍为 `318`，不依赖设备原生 fetch，继续兼容已有 `source_config` 数组及 `cookie` key → 字符串消息。

## 本地漫画导入

### 本地漫画导入与结果闭环

**章节追加与整书替换（HTTP-9-A）**：最新两端协商 `importChapterProtocol: 1` 后，「发送整本到设备」新建或替换当前作品，「仅发送本章到设备」按真实章号追加/更新；删除前面的编辑项不改变后面的章号，可在章节正文页设置章号。设备书架读取完整列表后，可点击「作为本地导入目标」精确选择已有本地 ID，概览显示名称/ID并核对所属设备。新版不按同名自动覆盖。

同一份整理内容在本次运行内保持稳定 `bookId`；清空生成新身份，重启后的草稿恢复仍按 P3-22 推进。重新整理旧作品时选择已有设备目标。HTTP 与互联共用设备提交层，新章节在独立目录完整保存/校验后切换索引；失败保留旧章。旧端单章继续发送为独立「书名 - 章名」单本，已选择 ID 目标时要求更新快应用；新版 header 未确认不静默退回旧分片。协议与设备存储引用详见配套快应用 `docs/LOCAL_CHAPTER_IMPORT.md`。

目标按钮位于对应设备漫画卡片内部，选中后显示「✓ 已选为导入目标」。整理页先显示目标作品的名称/ID/小封面、选择时页数/章数概要和所属设备，再显示「待发送草稿」。目标选择仅指定发送记录，现有章节清单和正文不会回读到编辑器；选中/切换/取消目标保留本地草稿，追加或更新仍使用用户选入的本地图片。

1. 保持 AstroBox 与设备连接，在插件「上传本地漫画」页选择图片和可选封面。
2. 点击上传。插件检查快应用版本，发出启动命令后等待启动窗口结束，再注册互联接收并协商设备能力；支持原生 HTTP 的设备完成健康检查和图片落盘探针后开始下载。
3. 手环显示下载进度，保存完成后可从离线书架阅读。不支持原生 fetch 的设备或旧客户端使用互联分片导入。
4. **双通道统一完成确认（P1-46）**：
   - 原生 HTTP 通道由快应用通过 `/result` 回传结果；
   - 互联分片通道通过 `importResultProtocol: 1` 协商：插件发出 `import_comic_done` 后进入「正在保存并写入索引…」等待态，快应用在文件落盘和索引提交全部完成后回传 `import_comic_result`，插件确认后展示「🎉 《书名》已成功保存到手环！共 N 页」；
   - 异常情况下（如部分分片缺失、写盘失败或索引提交失败）明确展示失败原因与已保存页数；若超时未收到确认则提示待核实，可通过 `import_comic_query` 重报原结果，不重复发送整本。
   - 未声明新协议的旧客户端保持向后兼容：发送 done 消息后提示「图片已发送，设备保存结果待核实」。

通常无需配置地址。AstroBox 原生网络转发由宿主建立 TCP 连接，当前 Windows + 小米手环 9 Pro 组合已由用户确认可使用 `127.0.0.1`。每次连接仍由设备端探针验证，不将这一实测结果视为所有平台/固件均可用。

需要备用地址时，展开「连接设置」，填写运行 AstroBox 的电脑/手机的 IPv4（无需端口）。该地址保存在 `http-address.txt`；旧版本保存的地址会自动作为备用地址，回环仍优先尝试。连接失败会明确提示重试。

### 共用图片成品处理

- HTTP 与旧互联的单本、多章、单章发送共用 `src/image_processor.rs`；正文优先级为 LVGL I8 > PNG > JPEG，封面宽度上限固定 80、小图不放大且始终使用普通图片。
- PNG 保留透明，JPEG/LVGL 合成白底；统一 Triangle 缩放，质量参数仅影响 JPEG。文件名和 HTTP MIME 根据成功生成的成品格式决定。
- 首版输入文件/母版读取上限 32MiB、输入 32Mi 像素/单边 65535、解码器分配预算 128MiB；单张成品最多 4Mi 像素/16MiB。LVGL 宽高为 1..2047，超长图等比缩小，概览保留实际尺寸及缩小说明；保宽切页见后续 P3-23。
- 选图失败不会进入正文；母版读取、解码、编码和预算失败明确显示文件/页码及阶段。旧互联在 header 前停止失败准备，HTTP 返回对应 JSON 错误状态。
- 母版和成品缓存原子提交，成品按版本/内容/用途/有效参数隔离并核对元数据、长度和完整性；损坏成品重新生成，重新选图可修复损坏母版。缓存命中保持相同成品。
- 当前编辑界面为有界素材缩略图。`product_preview()` 已提供从最终 JPEG/PNG/LVGL 成品生成展示图的底层接口，可视化预览、整本估算和切页交互在 P3-23 接入。

## HTTP 数据浏览回传

更新配套快应用与插件后，在「设备书架」点击「读取快应用数据」即可自动协商 `httpDataSync: 1`。数据浏览最低版本仍为 `318`，只有明确声明新能力的客户端才启用 HTTP，不要求先进入上传页测试连接。

- `request_data` 小消息下发本次同步 session、服务实例身份、回环/备用地址。
- 手环先 GET 健康接口并 POST 固定二进制探针（包含 NUL、`0x80`、`0xFF`），确认字节原样到达后再提交列表。
- 列表分批 POST，最多 16 条/批且请求体不超过 64KiB，累计元数据预算 8MiB；封面逐张读取、最多 16KiB/块，通过 PUT 发送原始二进制，无互联 Base64 分片。
- 插件按漫画 ID 与列表序号关联封面，最多暂存一张 2MiB 封面，解码后显示 100×200 边界内的缩略图；缺失、过大或无法解码的封面明确记为跳过。
- HTTP 请求可重试一次，重复批次/分块/完成回报幂等；旧同步 session 的迟到请求不能更新新列表。列表提交前探针失败可回退互联；提交后失败明确结束本次同步，重试由用户重新获取。

回传路由位于 `/control/sync/<session>/`：`POST probe`、`POST metadata`、`PUT covers/<列表序号>?offset=<字节偏移>&total=<长度>`、`POST skip`、`POST complete`。列表先显示，封面逐张补齐；全部列表及封面结果核对后才显示完成。

## 设备书架搜索与同步信息

- 漫画和漫画源各有名称搜索与清除按钮，忽略英文大小写及搜索词两端空格。搜索只过滤已收到的列表，每页最多 8 项，不重新请求手环；封面补齐保留筛选与有效页码。
- 来源卡片显示列表所属设备名称/地址、最近完整同步时间（UTC）及列表/封面完整性。时间和快照保存在本次插件运行内；插件重启后重新读取。
- 新数据到达前保留上次列表，启动/握手失败时明确说明仍显示旧数据；收到新批次后切换到目标设备快照，缺项、断连和超时显示未完成，不能把预分配空槽当作已接收条目。
- HTTP 与互联回传共用展示状态。HTTP 明确统计跳过封面；旧互联未回传的封面说明为无封面或缺失，不把列表完整等同于所有封面完整。
- 页面进入/渲染、读取/删除和宿主设备事件时核对连接，文案注明最近检查结果。操作确认及发送前核对原条目、列表代际和设备，避免筛选、刷新或换设备造成错位。
- 新版快应用协商 `deleteProtocol: 1` 后，按完整漫画 ID/源 key 删除；卡片显示身份以区分同名条目。插件保留条目并显示等待设备结果，收到文件/索引实际成功回报后才更新原快照；失败或部分失败保留可重试入口。
- 20 秒未收到最终回报、断连或发送异常时显示结果待核实，可点击「查询原删除结果」或重新读取完整列表。查询不会重新执行删除；设备重启或结果记录失效时通过列表核实，列表已无条目与设备确认删除分别展示。未确认的请求先核实再继续单条删除。
- 等待结果期间可重新读取；迟到结果只结算原请求，不直接调整已刷新的列表或其他设备数据，重复结果不会重复减数。删除不改变最近完整同步时间。
- 旧端继续名称删除及同名拦截，显示「命令已发送，待刷新核实」；部分列表禁用删除。新协议与列表的 HTTP/互联选择独立，无原生 fetch 的设备也可使用。

## 技术栈

- **语言**：Rust (Edition 2024, Rust 1.98.0)
- **架构**：WASI Preview 3 / Component Model (`psys-world-v4-http`)
- **UI 框架**：AstroBox PSYS Host V4 UI
- **通信**：Interconnect 消息通道 + 内建 HTTP 服务
- **主要依赖**：
  - `wit-bindgen` (0.62.0) - WIT 接口绑定 (async + inter-task-wakeup)
  - `waki` (0.5.1) - WASI 出站 HTTP 客户端
   - `serde_json` (1.0) - JSON 协议解析
   - `url` (2.5) - API 基础地址解析与规范化
  - `image` (0.25) - 图片缩放与编解码
  - `tracing` (0.1) - 结构化日志

## 构建与打包

### 前置要求

- Rust 工具链：1.98.0
- Target：`wasm32-wasip2`
- Python 3.x

### 构建与打包 ABP

```bash
# Windows / Linux
python scripts/build_dist.py --release --package
```

构建完成后，生成的 `.abp` 文件位于 `dist/` 目录。

## 权限声明 (manifest.json)

- `interconnect`：与手环快应用通信
- `thirdpartyapp`：检查并拉起手环快应用
- `device`：获取连接设备列表
- `register_interconnect_recv`：注册消息接收器
- `http-server`：启动本地 HTTP 服务
- `http-server.lan`：允许局域网设备访问本地 HTTP 端口

## 版本要求

- **WASI 版本**：3
- **API 级别**：4
- **AstroBox**：支持 API Level 4 的 AstroBox 版本
- **手环应用**：腕上漫画快应用 (`moe.yzf.comic`)

| 功能入口 | 最低快应用 `versionCode` |
| --- | --- |
| 漫画源同步（含 Cookie） | 318 |
| 数据浏览（含获取数据、删除漫画/漫画源） | 318 |
| 上传本地漫画（含单篇、多章节、单章上传和测试连接） | 382 |

低于最低版本时会显示当前版本和所需版本，停止该操作。插件加载时不提前注册设备互联；每次发出快应用启动命令后，按当前启动等待配置（1 秒）再注册和发送请求。等待通过定时器推进，旧会话定时器不会跳过等待。HTTP 上传复用已完成的启动握手，不再次启动应用。
